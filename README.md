# moneysplit

`moneysplit` 是一个只有标准库依赖的 Python 3 金额分摊库：把整数金额（单位「分」）
按权重、百分比或上限摊到若干份上，并支持把多笔金额结算成一组净额。

```python
from moneysplit import split, split_by_percent, allocate, merge, settle
from moneysplit import round_half_up, round_half_even, round_floor, round_ceil
from moneysplit import InsufficientCapacity
```

## 不变式

这五条是这套库的对外承诺，任何一条被破坏都算实现出错。

第一，**守恒**：任何一次分摊，各份之和都恒等于总额，总额为正、为负、为零都成立；
跨笔结算时，各笔金额之和也恒等于净额之和。

第二，**互逆**：把 `split` 的份数交给 `merge` 必须回到原始总额；把 `settle` 给出的净额
交给 `merge` 也必须回到各笔金额之和。

第三，**确定性**：实现不依赖随机源、墙钟、`dict` 迭代顺序或哈希种子，同样的输入永远
得到同样的输出，`settle` 逐条给出的记账记录的顺序也是确定的。

第四，**类型严格**：只接受 `int`。`float`、`Decimal` 这类近似值一律拒绝；`bool` 虽然
是 `int` 的子类，也必须被显式拒掉 —— 它们统统抛 `TypeError`。

第五，**可审计**：凡是「分摊出来的结果」与「各份逐份取整之后的和」之间有差异的地方，
`settle` 的记账记录里必须有对应条目，且拿这些条目去修正逐份取整的结果，能够重算出最终净额。

## 设计说明

分摊按权重比例进行，金额的整数分只保留到分位，不做任何浮点近似。分摊时先给每一份取它应得
份额的整数部分，再把「取整后还差的那几分」当作余额，按各份余数从大到小逐份补一，余数并列时
索引小的先补；这样每一分都有归属，总量不会漂移。权重全为零时按均分处理，余额同样按索引升序
逐份补。总额为负时，先对绝对值做同样的分摊，再把整组结果整体取负，因此负数场景下的守恒与
正数场景完全一致，符号只体现在最后一步。

百分比分摊接受两种写法：百分比之和等于 100 或者等于 1 都算合法，前者是「百分数」写法，
后者是「小数比例」写法，两种写法内部会归一到同一套整数运算上；各份先按比例取整，
剩下的余额全部给第一个非零份额。带上限的分摊在容量不足时会抛出 `InsufficientCapacity`，
异常里带着「还差多少分」这个数量，调用方可以直接拿去做下一次配平。空列表与单元素都是合法
输入；权重表为空时，只有总额为 0 才合法，否则报错。

跨笔结算把多笔金额用同一组权重逐笔分摊，第 k 笔的第 j 份份额累加到净额的第 j 项上，
所以单笔结算的结果与 `split` 完全一致，而多笔结算的结果等于各笔用 `split` 分摊后逐份相加。
每一笔各自的余额分配都会留下一条记账记录，记录的是该笔在哪一份上补了多少（含符号），
按「笔序号、份序号」升序排列；某一笔为负时，该笔先按绝对值分摊，再整体取负后累加，
它留下的记账记录同样带上负号。

`rounding` 里的四个取整模式接收精确的有理数（`int` 或 `fractions.Fraction`）并返回 `int`：
`round_floor` 朝负无穷取整，`round_ceil` 朝正无穷取整，`round_half_up` 在恰好半值时朝正无穷
取整，`round_half_even` 在恰好半值时向偶数取整。只有在恰好半值时后两者才互不相同，
其余情况下四个模式里相邻的两两关系也要能被观察出来。

## 用例要求

这一节同时是契约。

- 用例放在 `tests/` 下，用 `unittest` 写，`python3 -m unittest discover -s tests` 必须能跑通。
- **只能通过公开 API 观察行为差异**：禁止读源码、字节码、文件哈希、行号，禁止 import
  `_` 前缀的私有符号，也禁止访问 `moneysplit` 的私有属性。
- 不许用 `sleep`、随机数或墙钟让用例「碰巧」通过；用例必须确定性。
- 用例数量要求 ≥ 40；只加 `tests/` 下的文件，不要改 `moneysplit/` 下的实现，也不要改
  `mutcheck.py` 与 `check/` 下的固定验收程序。
- 杀伤率（由 `mutcheck.py` 算出）要求 ≥ 0.95。
- 对成对的语义近邻，用例集里必须存在能**把它们区分开**的输入：
  `round_half_up` 与 `round_half_even` 在半值上的差别、`split` 与 `allocate` 在上限边界上的
  差别、`split_by_percent` 对「和是 100」与「和是 1」两种写法的差别、`settle` 的单笔守恒与
  跨笔守恒的差别、以及负总额时符号的走向。

bash scripts/check.sh          # 固定验收，10 个场景
